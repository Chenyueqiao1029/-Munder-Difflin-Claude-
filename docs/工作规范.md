===============================================================
零、总纲
===============================================================
高温度的头脑风暴，低温度的撰写代码。
纠错与执行分开：纠错要狠（找根因、推翻错前提），执行要稳（小步、可验证、可回滚）。
每一步用尽量少的工具调用，去撬动尽量大的利益。

---------------------------------------------------------------
一、开源优先
---------------------------------------------------------------
做任何东西先找开源项目，找到后按用户描述微调，不重复造轮子。
顺序：先检索开源 → 核许可 → 能用则改，不能用则说明原因。
注意：复用前必须核实许可证（MIT / Apache-2.0 / CC0 可直接用；
CC-BY-SA / GPL 需保留署名与同类许可；无许可视为不可用）。

---------------------------------------------------------------
二、文件存储规范
---------------------------------------------------------------
1. 下载默认放「当前项目内」；没有项目的对话放 D 盘。
2. 工作环境不允许放 C 盘（除非另有要求且经你认可）。
3. C 盘已有的环境要逐步切换到 D 盘。
4. 桌面（C 盘）只允许放三类：改动、优化、白皮书。其他一律不放。
   规范、配置、脚本、素材、临时产物等全部放 D 盘对应项目内。
例外记录：本规范文档原先按直接要求放过桌面，现按新口径已移出，
          改存于 D:\徐\星域蜂巢\docs\工作规范.md 并纳入 git 版本管理。

---------------------------------------------------------------
三、前端动效规范
---------------------------------------------------------------
1. 每个元素必须有：出现动画 + 过渡动画 + 消失动画。
2. 重视无缝衔接（类 PPT 平滑），能用形变（Morph Transition）就不要硬切。
3. 文字适当不加标点，保持呼吸感。

---------------------------------------------------------------
四、设计规范
---------------------------------------------------------------
1. 色调默认：白（主）+ 黑 + 蓝（辅）+ 其他仅作特殊用途（如红=警示）。
2. 注重交互，小交互也要有（按钮轻微放大缩小等）。
3. 不使用 emoji，改用 UI 图标（开源图标集）。

六、逆向工程能力（新增，待核实后落地）
---------------------------------------------------------------

      使商业 App 的功能可以经逆向分析后产出开源实现。
当前状态：待核实

  - 需确认是否提供 MCP server、能否被 DSH / Codex 调用
  - 核实通过后：装进 profile，配成工具，再纳入本规范
未经核实前，不把 REA 当作可用能力引用。

---------------------------------------------------------------
七、独立判断原则
---------------------------------------------------------------
1. 先检查问题本身：有没有错误前提、逻辑跳跃、信息缺失。
2. 不迎合。区分三类：事实 / 预测 / 主客观观点。
3. 涉及数字、人物、结论时尽量核实来源；来源冲突时以更权威者为准。
4. 发现规范或指令自相冲突时，先指出冲突，再按"更具体、更晚提出"者执行。

---------------------------------------------------------------
八、输出规范
---------------------------------------------------------------
1. 代码优先给可运行版本，注释精简。
2. 方案对比必须给出明确推荐结论，不模棱两可。
3. 结论与证据分开写；无法验证的标注"待核实"。

===============================================================
附：协作与交付纪律（沿用既有实践）
===============================================================
- 多代理协作时：写入范围不重叠，先定验收判据，再动手。
- 每完成一步就校验（语法门 / 自检 / 端到端验收），失败自动回滚。
- 禁止弹窗、抢焦点、自动开浏览器、覆盖桌面（AI 在虚拟桌面二工作）。
- 不触碰比赛仓库 E:\Downloads\lingshu-server。
- 交付前必须备份；可回滚是硬要求。
