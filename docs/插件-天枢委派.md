# 天枢委派插件（`dsh-subagent-tianshu`）

把本机的**天枢（rivet）**接成 DSH 的一等公民工具：模型可以像调用 `subagent_codex` 那样，
直接委派给**不同星域**——每个星域有自己的**人设**和**独立工作目录**。

---

## 它是什么

- **引擎**：`plugins/dsh-subagent-tianshu/lib/tianshu-run.mjs` —— 从 Node 里无头跑天枢
  （`rivet -p "<task>" --json --skip-welcome --dangerously-skip-permissions`，或 `--goal "<task>" --budget N`）
- **插件**：`lib/index.js` —— 标准 Cordis provider（契约照 `@deepseek-ai/dsh-subagent-codex` 实测得出）
- **注册**：`cordis.patch.yml` —— 四个星域各注册一个 provider 实例

## 四个星域（各自的人设与工作目录）

| 工具名 | 星域 | 职守 | 工作目录 | 模式 |
|---|---|---|---|---|
| `subagent_tianshu_qiming` | 启明星域 | 破夜指引：先用最轻的探针把根因照到实地 | 继承父会话 | 一次性 |
| `subagent_tianshu_exec` | 执行星域（天梁·锚点之道） | 分段落地、分步开发、交可验证锚点 | `D:\徐\agent\tianshu-exec` | goal，budget 8 |
| `subagent_tianshu_approve` | 审批星域（瑶光·复现之道） | 审批与验收，每条结论要给复现方式 | `D:\徐\agent\tianshu-approve` | goal，budget 6 |
| `subagent_tianshu_fix` | 纠错星域（辅·诊断之道） | 排查根因、逻辑修正、细节润色 | `D:\徐\agent\tianshu-fix` | goal，budget 6 |

**想加第 5 个星域**：复制 `cordis.patch.yml` 里任一 `- insert:` 条目，改 `providerName` 与 `domain`
（`id` / `title` / `persona` / `cwd`）即可，**不用改代码**。

## 安装（四步）

```powershell
# 1) 装进目标 profile（会先备份，幂等）
python plugins\repair_and_install.py --profiles desktop

# 2) 放行"模型可见"的工具行（关键：maxDepth 必写，backgroundMode 不能写）
python plugins\grant_tianshu_tools.py --profiles desktop --apply

# 3) 验收：无头启动，问模型"列出你可用的工具名"
python plugins\grant_tianshu_tools.py --profiles headless --apply --boot
#   期望输出里出现 subagent_tianshu_approve / exec / fix / qiming

# 4) 桌面 app 热加载即生效，无需重启
```

> 影子 profile 验证：`--profiles desktop-canary`。正式装之前先在影子 profile 跑一遍更稳。

## 验收判据（全部实测过）

| 环节 | 判据 |
|---|---|
| 引擎 | `node plugins\dsh-subagent-tianshu\lib\tianshu-run.mjs "…"` → 退出码 0、拿到天枢真实答复 |
| 模块 | 在 profile 目录里 `import('@starhive/dsh-subagent-tianshu')` → 拿到 `name` / `inject` / `apply` |
| patch | `cordis.patch.yml` 是**单一 YAML 文档**，能解析出 4 条 insert |
| 真启动 | `dsh --profile headless headless "只回复两个字：正常"` → 退出码 0 |
| 加载凭证 | profile 的 `node_modules\@starhive\dsh-subagent-tianshu\load-proof.log` 里有四行 provider 注册记录 |

## 踩过的坑（三条，都是实测报错换来的）

1. **不能用 junction 装**：Node 按 junction 的**真实路径**解析 import，会找不到 profile 内的
   peer 依赖（报 `Cannot find package '@deepseek-ai/schemastery'`）→ **必须复制**。
2. **工具行必须写 `maxDepth: provider-managed`**：不写会报
   `tool-subagent: provider "…" cannot enforce maxDepth` 而拒绝激活。
3. **工具行不能写 `backgroundMode`**：那是"可续传后端子代理"用的，一次性委派写了会报
   `provider "…" does not support background…`。

另外：`handle.signal` **绝不能传 `undefined`** —— 框架会对它调 `removeEventListener`，
会崩 `Cannot read properties of undefined (reading 'removeEventListener')`；用
provider 自己的 `AbortController.signal` 兜底。

---

## 已知未验证项（诚实标注）

`attempt()` 的**返回对象形状**是本插件唯一没有对着类型验证过的地方，目前按最保守形状返回：

```js
{ stopReason: 'completed', output: [{ type: 'text', text: answer }], usage: null, meta: {...} }
```

**影响范围**：即使写错，也只会让**这一次委派**失败，**不会影响 app 启动**（模块加载层是语法合法、
且只依赖 profile 内已有的包）。
**要修的话**：对照 `@deepseek-ai/dsh-subagent` 的 `SubagentRun` 类型调整 `lib/index.js` 里
`attempt()` 的返回值即可（只此一处）。

## 卸载 / 回滚

```powershell
# 1) 还原两个被改过的文件（安装时都做过备份）
copy "C:\Users\<你>\.dsh\profiles\desktop\cordis.patch.yml.bak-tianshu-*" "...\cordis.patch.yml"
copy "C:\Users\<你>\.dsh\profiles\desktop\package.json.bak-tianshu-*"        "...\package.json"
# 2) 删掉插件目录
rmdir /s /q "C:\Users\<你>\.dsh\profiles\desktop\node_modules\@starhive\dsh-subagent-tianshu"
```
（`*.pregrant-*` 是"工具放行"那步的备份，同理还原。）
